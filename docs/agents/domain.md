# Domain Docs

This is a single-context repository. Domain terminology and architectural decisions are shared at the repository root.

## Before exploring

- Read `CONTEXT.md` when it exists.
- Read relevant records in `docs/adr/` when they exist.
- If these files do not exist, proceed without treating their absence as a problem. Create them lazily when a domain term or decision is actually resolved.

## Vocabulary

Use the glossary's terminology in issue titles, proposals, hypotheses, tests, and documentation. If a needed concept is not defined, record the gap for domain modeling rather than inventing an untracked synonym.

## ADR conflicts

If proposed work conflicts with an existing ADR, identify the conflict explicitly and state whether the ADR should be revisited.
